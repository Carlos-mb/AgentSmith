# Agent Smith

## Description

Agent Smith is a Python project for building an autonomous code agent.

The final system will receive programming tasks, ask an LLM for executable Python code,
execute that code in a restricted sandbox, observe the result, and iterate until a final
answer is produced.

The project targets two benchmarks:

- MBPP for small Python programming problems.
- SWE-bench for fixing issues in real repositories.

The project is still under development. The current implementation does not yet execute
the complete agent loop.

## System architecture

The intended architecture is:

1. The CLI loads an MBPP or SWE-bench task.
2. The benchmark adapter prepares the task and its limits.
3. The common agent loop asks an LLM for a response.
4. Python code is extracted from the response.
5. The code is sent to the sandbox.
6. The sandbox executes restricted Python code and returns an observation.
7. Calls to external tools go through an MCP client to an MCP server.
8. The loop continues until `final_answer` is called or a limit is reached.

The full architecture is not implemented yet.

## Agent loop

The required agent loop follows:

`Thought -> Code -> Observation`

The code-extraction and observation-building pieces exist, but the complete loop and LLM
integration are still pending.

## Sandbox design

The sandbox is intended to be the security boundary for Python generated by the LLM.

Currently implemented sandbox-related pieces:

- Configuration loading with `SandboxConfig`.
- Validation of positive execution-time and memory limits.
- Import allowlist matching.
- CLI argument parsing.
- `final_answer` control signal.

The actual isolated execution worker is not implemented yet.

The final sandbox must restrict:

- Imports.
- Filesystem access.
- Network access.
- Dangerous builtins.
- Execution time.
- Memory usage.

`final_answer` belongs to the sandbox and is not an MCP tool.

## MCP and tools

The MBPP MCP server currently exposes `run_tests`.

A real integration test has been performed through:

`MCP SDK -> stdio server -> run_tests -> Docker`

A correct candidate returns a successful test result, while an incorrect candidate returns
a failed test result. A failed candidate is different from an MCP protocol failure or a
Docker/environment failure.

The general-purpose MCP client used by the future sandbox is still pending.
